**Agentic Visual Quality Inspector**
*See the defect. Investigate the evidence. Decide what happens next.*

## 1. Problem statement and motivation

Automated visual inspection of manufactured parts often returns a single
classification or anomaly score with no notion of *how confident it should be*
or *what to do when the evidence is weak*. A borderline reading is silently
rounded to pass or fail. Poor-quality images get scored as if they were clean.
There is no audit trail explaining why a given verdict was reached.

InspectAI addresses the decision layer: it localizes visual anomalies with
classical computer vision, then runs an explicit agentic loop that evaluates
its own evidence and chooses a next action — re-inspect, pass, flag, or
escalate to a human — with a full decision trace.

## 2. Target users and real-world impact

Quality engineers and line operators on controlled-lighting inspection
stations (electronics surfaces, machined parts, coated panels). Impact: fewer
silent misses on borderline cases (they are escalated, not guessed), an audit
trail for every verdict, and an explicit "human review" path that keeps a
person in the loop where the evidence is ambiguous.

## 3. Related approaches and design rationale

Deep anomaly-detection models (e.g. PatchCore, PaDiM, autoencoders) achieve
strong results on datasets like MVTec AD but require a feature backbone, a
training/memory-bank step, and careful calibration. Given a **~1-day deadline**
and no GPU, we chose a **transparent classical baseline** that is reproducible,
fast (CPU, single-digit milliseconds), and easy to defend — then invested the
differentiation budget in the **agentic decision loop**, which is this
competition's special-award theme. This is a deliberate scope decision, not a
limitation we hide: see §10.

## 4. Dataset, licensing, and preparation

Real surface-defect datasets (MVTec AD and similar) are large and access-gated,
which is incompatible with a reproducible, offline, deadline-bound build. We
therefore use a **reproducible synthetic surface-defect generator**
(`src/vision/synthetic.py`) that:

- renders controlled-lighting product surfaces (gentle shading + fine grain),
- injects three labeled defect types with ground-truth masks — **scratch**
  (thin dark line), **spot** (dark/bright contamination blob), **dent** (soft
  shadowed ellipse),
- is fully deterministic from a seed, so anyone can regenerate the exact
  dataset and metrics.

Train/validation/test separation: the method is **not trained** — thresholds
are heuristics documented in code and tuned by inspecting the score
distribution, not fit to labels on the evaluation split. There is no model to
overfit to the test set. The synthetic data is generated by our own code
(no third-party license).

**This is a documented stand-in, not a real-world benchmark** — see §10.

## 5. Computer vision implementation (substantive OpenCV 5 usage)

Verified engine: **OpenCV 5.0.0** (`cv2.__version__ == "5.0.0"`, installed from
`opencv-python==5.0.0.93`). OpenCV is the core of every processing step, not a
decorative import:

| Stage | OpenCV 5 operations | File |
|---|---|---|
| Decode & validate | `cv2.imdecode` (+ magic-byte sniffing) | `preprocessing.py` |
| Normalize | `cv2.resize` (INTER_AREA), `cv2.cvtColor` | `preprocessing.py` |
| Quality | `cv2.Laplacian` (focus), luma stats | `image_quality.py` |
| Anomaly map | `cv2.GaussianBlur` background model, `cv2.blur` box stats, absolute high-pass residual | `detector.py` |
| Segmentation | thresholding, `cv2.getStructuringElement`, `cv2.morphologyEx` (open/close) | `detector.py` |
| Regions | `cv2.connectedComponentsWithStats` | `detector.py` |
| Visualization | `cv2.rectangle`, `cv2.putText`, `cv2.applyColorMap`, `cv2.addWeighted` | `detector.py` |

### Detection method (defensible, deterministic)

Surface defects are **compact, high-contrast** deviations from an otherwise
smooth surface. The detector:

1. denoises lightly (`GaussianBlur 3×3`);
2. builds a **broad illumination background** via a large-sigma Gaussian and
   subtracts it, leaving an **absolute high-pass residual** (in gray levels) —
   gentle shading and uniform grain cancel, compact defects survive;
3. averages the residual over a small window so a defect forms a coherent blob;
4. maps the residual to [0,1] with a **fixed gray-level scale** (`Z_SCALE`),
   preserving absolute contrast (clean ≈ 0, strong defect ≈ 1);
5. thresholds (absolute floor OR per-image guard), cleans with morphology,
   suppresses a thin unreliable border, and extracts connected components;
6. measures each region (bbox, area, fill ratio, mean score) and computes an
   image-level score from the peak contrast and the dominant region's coherence.

This is explicitly a **visual-anomaly localizer**, not a certified defect
detector (§10).

## 6. Agent architecture and perception–decision–action loop

`src/agent/controller.py` is an explicit, bounded state machine. Each decision
is a **pure function of the real measurements** produced by OpenCV, and every
step is recorded in a structured decision log (`decision_log.py`).

Policy (deterministic; thresholds documented in code):

1. **Perceive/evaluate quality.** If quality fails → **human review** (a
   degraded image is *never* declared defective).
2. **Analyze** the usable image.
3. **Choose** on the actual result:
   - `score ≥ SCORE_HIGH (0.55)` → **potential anomaly** (terminate);
   - `score < SCORE_LOW (0.50)` → **no anomaly detected** (terminate);
   - otherwise **borderline** → the agent *chooses a different action*:
     `run_targeted_reinspection` with a **lowered threshold**.
4. **Observe again / compare.** If re-inspection corroborates → potential
   anomaly; else → **human review** (uncertain evidence is surfaced, never
   silently passed).
5. **Terminate safely.** Iterations are bounded (`max_iters`); hitting the cap
   yields human review, not a guess.

The first visual result **demonstrably** steers the next action: on the
evaluation set, faint-scratch samples (score ~0.45–0.50) land in the grey zone
and trigger re-inspection, whereas clear defects terminate immediately. Tools
exposed: `assess_image_quality`, `analyze_image`,
`run_targeted_reinspection`, `compare_analysis_results`, `request_human_review`
(`src/agent/tools.py`).

## 7. AWS architecture and deployment

The cloud component is the **FastAPI inspection API** (`src/api/routes.py`),
containerized (`Dockerfile`) and intended for **AWS App Runner** (image in
Amazon ECR). It validates input, enforces an 8 MB cap, runs the full pipeline
server-side, and returns structured results + base64 annotated images, with a
`/health` endpoint for the platform health check.

**Deployment verification (honest):** the API was verified running locally via
`uvicorn` (`/health` → OpenCV 5.0.0; `/inspect` → correct detection with
images). The container was **not** built (local Docker daemon down) and
**nothing was deployed to AWS** (no credentials/CLI). The deployment steps are
complete and ready in `deployment/aws-deployment.md` but are **UNVERIFIED**.
No paid infrastructure was created. See the deployment doc for IAM, env vars,
and cost notes.

## 8. Experimental methodology and actual results

Protocol fixed **before** reading results: balanced synthetic set (40 normal /
40 defect, seed 7); image-level detection via (a) a fixed-threshold baseline on
the detector score and (b) the agent's status; ROC-AUC on the raw score;
pixel-level IoU on defect masks; latency; agent iterations and escalation rate.
Reproduce with `python -m src.evaluation.evaluate`.

Actual results (`artifacts/evaluation_results.json`, OpenCV 5.0.0):

| Metric | Baseline (score ≥ 0.49) | Agent |
|---|---|---|
| Precision | 1.000 | 1.000 |
| Recall | 0.975 | 0.975 |
| F1 | 0.987 | 0.987 |
| Accuracy | 0.988 | 0.988 |
| FP / FN | 0 / 1 | 0 / 1 |
| Escalation rate | — | 0.0375 |

Other measured values: **ROC-AUC 0.994**; best-F1 threshold 0.515 (F1 0.987);
**pixel IoU** mean 0.704 / median 0.791 (n=40); **latency** detector mean
4.2 ms (p95 4.7 ms), agent mean 6.0 ms (p95 7.8 ms).

## 9. Baseline comparison

The agent matches the baseline's image-level accuracy (F1 0.987) while adding
bounded uncertainty handling: it escalates ~3.75% of cases — the genuinely
borderline faint scratches — to human review rather than committing to a guess,
at a cost of ~2 extra milliseconds mean latency. In short: **same accuracy,
plus an explicit, audited uncertainty path**, which is the agentic value-add.
On this easy synthetic set the accuracy headroom is small; the agent's benefit
would grow on harder, noisier real-world inputs where borderline cases are more
common.

## 10. Limitations, failure cases, privacy, responsible use

- **Synthetic data.** Metrics are an upper-bound sanity check on clearly
  separable defects, **not** a real-world benchmark. Real defects (subtle
  texture changes, low-contrast cracks, lighting variation) are harder.
- **Classical method.** No semantic understanding; it flags local contrast
  deviations. It will miss defects with contrast comparable to surface texture
  and may flag benign marks. One such **false negative** (a very faint scratch)
  is present in the evaluation set.
- **Thresholds are heuristics**, tuned to the controlled-surface assumption —
  **not calibrated probabilities**. They require re-tuning per product/line.
- **Not a certified inspector.** Output is decision support; a qualified human
  must verify findings before action.
- **Privacy/responsible use.** See `docs/responsible_use.md`.
